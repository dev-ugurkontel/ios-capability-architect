# Support

## Where to ask

- Use GitHub Discussions, when enabled, for setup questions, architecture discussions, and usage help.
- Use the bug report template for reproducible defects in a skill, plugin, MCP tool, validation script, or bundled runtime.
- Use the most specific domain correction template for missing or inaccurate evidence records.
- Use the feature proposal template for new tools, workflows, or supported use cases.
- Follow [SECURITY.md](SECURITY.md) for vulnerabilities and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for private conduct reports.

Before opening a request, search existing issues and confirm that you are using the component's supported runtime, a clean locked installation, and the latest applicable release.

## What to include

Provide the affected skill or plugin, its version or commit, operating system, runtime and package-manager versions, host version where relevant, exact command or tool name, expected behavior, actual behavior, minimal reproduction, and sanitized logs. Never post credentials, signing material, account identifiers, private project content, or personal data.

## Support boundaries

Maintainers can help with this repository's documented behavior. They cannot grant third-party access, approvals, credentials, private capabilities, legal advice, or compliance certification. Technical recommendations must be validated against the target project's actual platform, account, runtime, deployment, security, and policy context. Component documentation may define additional support boundaries.

This is a community-maintained open-source project. Response times are best effort and no service-level agreement is provided.
