# Full-response quality gate

Before delivering a full architecture analysis, verify that it:

- distinguishes product requirements from technical requirements;
- states assumptions and asks no more than three architecture-changing questions;
- shows only relevant technologies;
- separates stable, beta, deprecated, managed, regional, language, and hardware-dependent features;
- separates runtime permissions, purpose strings, Xcode capabilities, entitlements, background modes, and extensions;
- explains on-device and cloud boundaries;
- does not promise background timing or uninterrupted execution;
- names real-device and Simulator limitations;
- provides a proportionate SwiftUI-first architecture;
- provides dependency-ordered implementation and test plans;
- covers privacy, security, and App Store risks for sensitive data;
- cites each important technology with a verified official Apple URL;
- ends with the actual documentation verification date.
